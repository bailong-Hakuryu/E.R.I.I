# Orchestrate host-supplied relationship event extraction in the core

E.R.I.I. will own the versioned RelationshipEventExtractorV1 contract and the normal Relationship Adjudication processing lifecycle while the host supplies the concrete extractor or model implementation and its credentials. The Engine reads the accepted Source Transcript, assembles the permitted fact context, validates exact evidence citations and strict output boundaries, records an Extractor Descriptor, freezes the resulting candidate batch, applies retry policy, and passes valid candidates to the deterministic relationship adjudicator; the extractor never writes history, state, reflections, or persona changes. Its strict Relationship Event Extraction Decision is either `kind=candidates` with at least one bounded, persona-reflection-free Relationship Event Candidate or `kind=no_relationship_event` with no candidates, while empty, malformed, persona-shaped, or contradictory results fail processing rather than inventing an event. Manual candidate submission remains an explicit testing, correction, and expert integration path tied to an existing `source_turn_id` and distinct processing identity, not the default host workflow. No provider-specific model dependency or hidden worker lifecycle is added to the core.
