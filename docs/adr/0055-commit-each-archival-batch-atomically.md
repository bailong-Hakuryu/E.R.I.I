# Commit each archival batch atomically

All Timeline and MemoryNode artifacts extracted from one accepted Archival Submission form one Archival Batch and become visible together only after validation and a successful storage commit. SQLite uses one transaction. Under its supported local, single-process contract, FileStorage loads a versioned per-relationship aggregate containing nodes and structured timeline entries, writes the complete after-image to a same-directory temporary file, flushes it, and publishes it with one atomic replacement; it does not claim that two sequential file replacements are atomic, nor does it extend this guarantee to network filesystems or multiple processes sharing a root. A failed attempt exposes none of the batch, and narrow recovery of the exact batch already bound to one Commit Permit belongs to this lifecycle contract; the later `0.4.0a6` milestone remains responsible for duplicate host submissions and broader delivery idempotency.
