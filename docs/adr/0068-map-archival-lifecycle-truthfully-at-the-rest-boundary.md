# Map archival lifecycle truthfully at the REST boundary

The reference REST server keeps `POST /api/v1/remember` but returns `202 Accepted` with a pending receipt and receipt location for queued acceptance, or `200 OK` with a terminal receipt for inline completion. Invalid submissions return `422` without a receipt, missing archival capability or a closing Engine returns `503` without a receipt, and scoped `GET /api/v1/archivals/{archival_id}` returns `200` or indistinguishable `404` for unknown and mismatched scopes. An accepted inline Retryable Archival Failure returns `503`, a Permanent Archival Failure returns `500`, and both carry a sanitized Archival Error Envelope and receipt. Raw exception strings are never exposed, and this mapping does not make the unauthenticated reference server production-safe.
