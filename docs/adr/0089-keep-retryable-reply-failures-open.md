# Keep retryable reply failures open

A retryable Reply Attempt failure will leave its Turn Record `open` so the host can retry generation, Continuity Evaluation, or delivery preparation with the same stable `turn_id`; no hidden timeout or background cleanup abandons it. Operational attempt history retains only the attempt number, stage, capability descriptor, time, and sanitized failure classification, never an undisplayed draft, full prompt, internal reasoning, credential, or provider error body in the Source Transcript. `abandon_turn()` is an explicit terminal operation reserved for user cancellation, host termination, or a classified unrecoverable error. Both `completed` and `abandoned` are immutable terminal states: an identical `complete_turn()` retry returns the existing Source Turn Receipt, a different completion payload conflicts, and concurrent completion or abandonment uses one atomic first-writer-wins transition while the losing operation receives a typed Turn Terminal Conflict.
