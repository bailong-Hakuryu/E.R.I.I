# Use one public turn recording lifecycle

E.R.I.I. will use one authoritative Turn Recording lifecycle for accepting new interaction sources. `begin_turn()` persists the stable identity and User message before generation; `complete_turn()` atomically appends the displayed Agent reply, continuity assessment, delivery disposition, and Source Processing Plan, seals the Source Turn, and returns its non-sensitive receipt; `abandon_turn()` truthfully terminates an unanswered record without creating a processing plan. `record_turn()` remains the one-shot atomic convenience boundary for hosts that already possess both visible messages, but writes the same ledger and does not create another source path. Archival, relationship adjudication, retry, query, and historical reprocessing APIs reference the completed identity instead of receiving independent copies of the messages. The existing `remember()` API and raw-Source-Turn relationship adjudication form remain deprecated compatibility facades throughout `0.4.x`, receive no new capabilities, and may be removed in `0.5.0`. Compatibility cannot safely infer that two independently submitted legacy calls represent the same interaction, so hosts that need unified memory and relationship processing must adopt the Turn Recording lifecycle or explicitly carry its returned source identity.
