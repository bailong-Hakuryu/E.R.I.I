- 密钥加载仅 0.3 微秒，缓存策略有效
- 所有操作均在微秒级别，对应用性能影响可忽略

### 日志系统 (Logging)

| 操作 | 平均耗时 | 评级 |
|------|---------|------|
| 文本日志 | 0.0039 ms | ⭐⭐⭐⭐⭐ 优秀 |
| JSON 日志 | 0.0045 ms | ⭐⭐⭐⭐⭐ 优秀 |
| 审计日志 | 0.0052 ms | ⭐⭐⭐⭐⭐ 优秀 |

**分析**:
- 文本日志最快，仅 3.9 微秒/条
- JSON 日志略慢，但仍在 5 微秒内
- 审计日志包含额外元数据，耗时稍长但仍然优秀
- 对于高吞吐量场景，建议使用异步日志

### 错误处理 (Error Handling)

| 操作 | 平均耗时 | 评级 |
|------|---------|------|
| 错误创建 | 0.0007 ms | ⭐⭐⭐⭐⭐ 优秀 |
| 带恢复建议 | 0.0009 ms | ⭐⭐⭐⭐⭐ 优秀 |
| 错误格式化 | 0.0010 ms | ⭐⭐⭐⭐⭐ 优秀 |
| 错误序列化 | 0.0002 ms | ⭐⭐⭐⭐⭐ 优秀 |

**分析**:
- 错误创建非常轻量，不到 1 微秒
- 错误格式化（字符串）开销最大，但仍然可接受
- 序列化到字典非常快，适合 API 响应
- 即使在异常路径，性能影响也极小

### 存储操作 (Storage)

## 🎯 性能优化建议

### 已实施的优化

1. ✅ **凭据缓存**: 密钥加载后缓存，避免重复环境变量读取
2. ✅ **日志处理器复用**: 避免重复创建处理器
3. ✅ **错误上下文懒加载**: 只在需要时格式化
4. ✅ **正则表达式编译**: 密钥检测模式预编译

### 可选优化 (当前不需要)

#### 1. 异步日志
**场景**: 高吞吐量应用（> 10,000 日志/秒）

```python
from erii.core.logging import StructuredLogger
from logging.handlers import QueueHandler
import queue
import threading

log_queue = queue.Queue()
handler = QueueHandler(log_queue)
logger.addHandler(handler)
```

**收益**: 将日志 I/O 移到后台线程，减少主线程阻塞

#### 2. 日志批处理
**场景**: 审计日志量很大的场景

```python
class BatchAuditLogger:
    def __init__(self, batch_size=100):
        self.batch = []
        self.batch_size = batch_size
    
    def log_operation(self, operation, status, **context):
        self.batch.append({'operation': operation, ...})
        if len(self.batch) >= self.batch_size:
            self.flush()
    
    def flush(self):
        # 批量写入
        pass
```

**收益**: 减少 I/O 次数，提高吞吐量

#### 3. 错误消息缓存
**场景**: 相同错误频繁抛出

```python
from functools import lru_cache

class OptimizedError(ERIIError):
    @lru_cache(maxsize=128)
    def __str__(self):
        return super().__str__()
```

**收益**: 避免重复格式化相同错误消息

## 🔍 性能瓶颈分析

### 当前系统中不存在明显瓶颈

基于性能测试结果：
- ✅ 无单点性能瓶颈
- ✅ 所有操作均在微秒级别
- ✅ 内存使用合理
- ✅ CPU 使用率低

### 潜在瓶颈（实际应用层面）

1. **I/O 操作** (非框架层面)
   - 数据库查询
   - 文件读写
   - 网络请求
   
   **建议**: 使用连接池、缓存、异步 I/O

2. **大量日志输出**
   - 每秒数万条日志
   
   **建议**: 使用异步日志、日志采样

3. **密集型错误处理**
   - 在循环中频繁抛出异常
   
   **建议**: 优化业务逻辑，减少异常使用
